The shared `git-and-prs` `AGENTS.md` block asks for a Codex review after every push, and the merge gate says why it waits for one: agents now comment `@codex review` on a pull request again after every push to it, however small, not only after a substantive one, because Codex reviews a pull request when it is opened for review, marked ready or asked, never on a push, and where `merge-gate.yml` has `require-codex-review: true` the gate needs a finished review of the head commit itself (a pull request whose later docs-only pushes went unasked waited on "Codex review of this commit" until it was merged past the gate). With `require-codex-review`, the gate's pending text now says which it is, after the unchanged words "Codex review of this commit": `(requested, running)` when Codex's review state line names the head as queued or running, `(requested)` when a comment starting with `@codex review` (any case) from the repository's owner, a member or a collaborator came after the head was pushed (a bot's or an outsider's doesn't count), `(none requested yet: comment @codex review)` otherwise, and nothing more for a head with no workflow run yet, each as of the gate's last run (Codex's own comment when it starts runs it again, through the threads caller's `codex-comment` job); the push is the earliest of the head's pull request runs, which GitHub creates when the commit arrives, not the commit's own dates. The gate doesn't post the request itself: Codex answers an `@codex review` from `github-actions[bot]` (a workflow's token) with "To use Codex here, create a Codex account and connect to github" and reviews nothing (tried twice on throwaway drafts, where the owner's request on the same head started a review within 20 seconds), and a GitHub App's bot (the fleet-bot App's included) has no Codex account either. No input, permission, status name or check changes. Why a major: the block changes what an agent does with an existing setup, as #100's `starting-work` bullet did. What apps do: from the migration issue, `fleet sync --to vX.Y.Z` (the block is the whole change; nothing outside the markers is edited); anything that looks for "Codex review of this commit" at the start of the gate's pending text still finds it, and anything that expected those words to be the whole of it has to match them as a prefix now.
