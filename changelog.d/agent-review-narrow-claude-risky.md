kind: breaking

`agent-review.yml`'s second review no longer counts a skill's reference documents as always risky (#140, the owner's request): `second-review-always`'s default is now `.github/**`, `.claude/**` and the exception `!.claude/skills/*/references/**/*.md` (`ALWAYS_RISKY` in `fleet_tools/agent_review.py`), so a pull request whose only `.claude/` changes are `.md` files under `.claude/skills/<name>/references/` (a verify skill's regenerated `references/feature-map.md`, say) gets the passing "Not a risky pull request" instead of a full second review. Everything else under `.claude/` stays risky, failing closed on what it doesn't recognize: the settings, hooks, agents, commands, rules and `CLAUDE.md`, a skill's `SKILL.md`, scripts and any other file, a file in `references/` that isn't `.md`, a file named `SKILL.md`, `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md` or `AGENTS.override.md` anywhere, and a nested `.claude/` (or any other part starting with `.`) inside `references/`; `.github/**` is unchanged. A line starting with `!` is now an exception within its own list (`second-review-always` or `second-review-paths`, so one in `second-review-always` never reaches the paths a caller adds), matched exactly and only against a plain path (ASCII letters, digits, `.`, `_`, `-` and `/`, with no empty part and no part after the first starting with `.`). The matching gets stricter at the same time: a risky glob matches any case, and a path as git quoted it, as the name it stands for and with `..` resolved; a rename still counts its old path. That fixes a bypass: `files.txt` comes from `git diff --name-status`, which quotes a name with a byte outside printable ASCII, a `"` or a `\`, and a quoted name matched no glob, so a pull request adding `.claude/agents/évil.md` or `.github/workflows/a"b.yml` wasn't risky. The reason in the comment shows a character that isn't printable escaped. The second review's prompt gains point 6 (`.github/agent-review/second-review.md`, a prompt change): anything that would make a reference more than a document (a hook, a settings entry, a `SKILL.md`, a script or an `@` import that runs, sources, loads or imports one, or a symlink to one) is a blocking finding. The plugin's `review-guidance` skill and `fleet-reviewer` agent say the same. Why a major: no input is added or removed, but an input's default changes what an existing setup does, as reference-only pull requests stop getting the second review and ones with an odd spelling or a quoted name of a risky path start getting it. fleet's own caller keeps `.claude/**` with no exception. What apps do: nothing is required; an app that wants its references reviewed passes `second-review-always` as `.github/**` and `.claude/**` without the exception (or lists `.claude/skills/**` in `second-review-paths`, which requires its `.github/agent-review/invariants.md`), and Darkroom's, Waypoint's and Runway's callers, whose comments say `.claude/**` always counts, update those comments (`docs/adopting.md`, "Which paths are always risky"; the threat model is in `docs/agent-review.md`, "The always-risky paths"). Tests: `tests/test_agent_review_risky.py` (`ClaudeRule`: a reference-only change not risky; settings, hooks, agents, commands, `SKILL.md` and scripts under a skill risky; mixed changes risky; renames out of a risky path, odd casing, `..` and quoted names from a real `git diff` risky; the workflow's default equal to `ALWAYS_RISKY`), and the Self-test's not-risky case now carries a reference document.
