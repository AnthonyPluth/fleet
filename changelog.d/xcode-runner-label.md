`fleet checks` accepts a pinned Xcode runner for a job that only macOS can build: `runs-on: xcode-<number>   # hosted: <why>` (for example `xcode-27   # hosted: the iOS 27 SDK needs Xcode 27`) passes as `macos-<number>` does, with the same `# hosted:` reason required. `xcode-<number>` is GitHub's hosted Apple Silicon image that carries that Xcode (the actions/runner-images README lists "Xcode 27 | arm64 | `xcode-27` or `xcode-27-xlarge`", generally available since 2026-10-16), added by an owner decision of 2026-11-18 so Waypoint can build its iPhone app with Xcode 27: App Store Connect's warning ITMS-90725 requires the iOS 27 SDK from April 2027, and `macos-26` tops out at the iOS 26.5 SDK. The number of both `xcode-<number>` and `macos-<number>` is now ASCII digits only (`macos-` took any Unicode digit; no real label changes). `xcode-latest`, `xcode-`, a suffix (`xcode-27-beta`, `xcode-27-xlarge`), anything after the number but the comment, and an `xcode-<number>` runner without the reason still fail. Every other runner rule and check is unchanged. What apps do: pin to the release, then use `runs-on: xcode-<number>   # hosted: <why>` where a job needs that Xcode. `docs/adopting.md`; `tests/test_checks_workflows.py`.
