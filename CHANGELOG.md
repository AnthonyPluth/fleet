# Changelog

Every change to fleet is a change to three repositories' CI, so each one is listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and fleet uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html): a removed or renamed input, a renamed status or a removed `AGENTS.md` block is a major change unless the old behaviour stays the default.

## [Unreleased]

### Added

- `agent-review.yml` takes `second-review-always` (default `.github/**` and `.claude/**`, as before): the changed paths that always make a pull request risky. Fleet's own caller narrows it to every reusable workflow (the ones the apps call by pinned reference), the caller itself, `.github/scripts/**`, `.github/agent-review/**`, `.github/CODEOWNERS`, `.claude/**`, `plugins/**` and `shim/**`. Only fleet's own `ci.yml` and `self-test.yml`, `dependabot.yml` and docs skip the second review: no app calls them and they run with no secrets or write tokens beyond what their own jobs name. A test fails if a reusable workflow is ever left out of the list.
- A test pinning `security.yml`'s zizmor step (the `zizmor-paths` default, the env mapping, how the paths split) and a fallback to `.` when the input is empty.
- `security.yml` takes a `zizmor-paths` input (default `.`, the whole tree, as before); fleet's own self-test passes `.github` so workflow files kept as test fixtures aren't audited as the repository's own.
- The FLEET_REF convention now requires the fleet checkout only in a workflow that runs fleet's own files, after the caller's checkout and before the first fleet file is used. `FLEET_REF` and `fleet-ref` stay on every reusable workflow.
- The scaffold: `VERSION`, the `fleet` command (`fleet --version`, a subcommand registry, `fleet self-check`), `[tool.fleet]` config reading, `make check`, the "fleet CI" and "Self-test" workflows, and the repository's templates and policies.
- The FLEET_REF convention for reusable workflows, held by `fleet self-check`.
- The reusable security scans (`security.yml`, `workflow_call`), the union of Waypoint's and Runway's: Semgrep with the app's own rules and their example check, npm audit, Trivy over the files and the image, zizmor and OpenSSF Scorecard, with inputs `code-paths`, `semgrep-paths`, `semgrep-examples`, `web-dirs`, `image-paths`, `dockerfile`, `sarif-upload` (`false` fails the job on findings, for a repository without code scanning), `scorecard`, `runs-on` and `fleet-ref`; the scripts `.github/scripts/security-changes.sh`, `security-semgrep.sh` and `drop_suppressed.py`. `tests/test_security_changes.py` checks the `changes` job's outputs per app from the fixtures in `tests/fixtures/security/`; the self-test runs the scans over fleet and checks that a planted Semgrep finding fails without SARIF upload.
- The deep-scan runbook (`docs/deep-scan.md`, written against claude-security 0.11.0) and the `deep-scan-due` reusable workflow (`.github/scripts/deep_scan_due.py`), which opens one "Deep security scan due" issue unless one is open; `tests/test_deep_scan_due.py` drives it against the fake `gh` in `tests/fakes/security/`, and the self-test runs it in dry run.
- `fleet checks`: the union of Waypoint's and Runway's `tools/fleet_checks.py` (migrations, commit trailers, removed or skipped tests, workflow conventions, images, skills and generated files), configured by `[tool.fleet]`, plus the app's own `extra-checks`; `fleet no-comments` and `fleet coverage-floor` (opt-in), `fleet next-version` (replaces `next-version.sh`) and `fleet test-timings`. Keys in `docs/adopting.md`, decisions in `docs/drift.md`.
- The reusable merge gate (`merge-gate.yml`, `workflow_call`) and its one script (`.github/scripts/merge-gate.sh`), replacing Waypoint's and Runway's copies: inputs `sha`, `pr`, `required-workflows`, `ignored-workflows`, `required-statuses`, `ignored-apps`, `poll-seconds`, `poll-attempts`, `automerge-dependabot`, `after-merge-workflows`, `dry-run` and `fleet-ref`. A Dependabot pull request that changes an `AnthonyPluth/fleet/` reference passes the gate but is left for the owner to merge. The self-test runs it in dry run on fleet's own pull request; `tests/test_merge_gate.py` drives the script against the fake `gh` in `tests/fakes/gh`.
- The shared `AGENTS.md` blocks (`agents-md/sections/`: `starting-work`, `working-in-a-container`, `mistakes` opening with the rule "A mistake that repeats gets a check", `git-and-prs`), shipped with the package; `fleet sync --to vX.Y.Z` writes them between `fleet:begin`/`fleet:end` markers and writes `.fleet/version`, and `fleet drift` fails on an edited block, markers and `.fleet/version` at different versions, or content newer than (or in another major from) the workflow pins. fleet's own `AGENTS.md` and both fixture consumers carry the blocks; `tests/test_sync_agents.py`, `tests/test_drift.py`.
- The reusable agent review (`agent-review.yml`, `workflow_call`), the first review of every agent's pull request, extracted from Waypoint's and Runway's: inputs `generated`, `first-review`, `budget-usd`, `max-turns`, `merge-gate-workflow`, `dry-run`, `fake-review` and `fleet-ref`, the secrets `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` passed by name, and outputs `verdict` and `description`; the model is Sonnet, fixed. `ready_for_review` reviews only a head without an "Agent review" status, label events run no first review, and a consumer without `.github/agent-review/context.md` gets an `error` status naming the file. Findings gain a required `kind` (the AGENTS.md "Mistakes that keep coming back" item) and an optional `check`, and the comment's third hidden line carries them as data for `FLEET-MINING`. `fleet_tools/agent_review.py` (also `fleet agent-review`), `.github/scripts/agent-review-run.sh`, one generic prompt with the app's `context.md`, the locked Claude Code in `.github/agent-review/` (Dependabot npm entry), fleet's own `context.md` and caller (`agent-review-caller.yml`), the stub reviewer `tests/fakes/claude`, `tests/test_agent_review.py`, `tests/test_agent_review_workflow.py`, three dry-run self-test jobs and `docs/agent-review.md`.
- The second review (`FLEET-SECOND-REVIEW`): the `second-review` and `second-report` jobs in `agent-review.yml`, on `claude-fable-5-1` (fixed, no input), for pull requests labelled with one of `second-review-labels` (default `safety-critical,security`) or changing a path in `second-review-paths` (`**` globs; `.github/**` and `.claude/**` always count), as the "Second review" status and a `<!-- second-review -->` comment that says why; a pull request that isn't risky gets a passing "Not a risky pull request". Inputs `second-review-labels`, `second-review-paths`, `second-review-budget-usd` (`10`), `second-review-max-turns` (`120`) and the self-test's `fake-event`; outputs `second-verdict` and `second-description`. `labeled` and `unlabeled` run only this job, and an `unlabeled` by anyone but the repository owner changes nothing. A label event that will run a review first marks the head's "Second review" pending and restarts the merge gate (`second-pending`), and only the newest "Second review" status counts as a head's verdict. `agent_review.py second …` and `risky`, the prompt `.github/agent-review/second-review.md`, fleet's own `.github/agent-review/invariants.md` (required of a consumer that sets `second-review-paths`), `tests/test_agent_review_risky.py`, six dry-run self-test cases and the second review in `docs/agent-review.md`.
- Finding outcomes (`FLEET-FINDING-OUTCOMES`): every review finding has an id (the first 8 hex digits of SHA-256 over its kind, file and normalized title), shown as `f:1a2b3c4d` after its title and carried in the findings line; the comment's fourth hidden line (`agent-review-outcomes`, and `second-review-outcomes` for the second review) records each id as `open` or `resolved` (gone from a full review, or from an incremental one whose diff touched its file), at most 200 entries and 16 KB with the oldest resolved dropped first; the owner's `/fleet dismiss f:<id> <reason>` conversation comments (`author_association` `OWNER`, ten characters of reason at least) show the finding as dismissed with its reason and never change a status or the merge gate. The report jobs check out fleet's tools (`contents: read`) to merge the record, `plan` gains a `touched` output, `fleet_tools/review_outcomes.py` is the shared reader and `fleet review-outcomes --repo OWNER/NAME --pr N [--json]` prints the merge; `tests/test_review_outcomes.py`, the self-test job `finding-outcomes` (`.github/scripts/finding-outcomes-self-test.sh`, with the stub reviewer) and the section in `docs/agent-review.md`.
- Review mining (`FLEET-MINING`): `fleet review-mine` (`fleet_tools/review_mine.py`) and the reusable `review-mining.yml` (`workflow_call`; inputs `days`, `dry-run`, `fleet-ref`; `issues: write`, `pull-requests: read` and `contents: read` for the caller's `AGENTS.md`; no secrets), which keeps one "Repeated review findings" issue per repository (label `review-mining`), rewritten each run: the kinds of review finding on two or more pull requests in the window (or checked and still appearing), their state from `AGENTS.md`, the pull requests, when last seen and the proposed check, with a stable `row:` id and a "becomes an Agent task" checkbox per row whose tick and link survive a rewrite; the same table goes to the job summary. It reads only the third hidden line of the reviews' own comments, which now also carries each finding's `check`. Callers schedule it monthly (`17 6 1 * *`) or weekly (`17 6 * * 1`). `tests/test_review_mine.py`, a dry-run self-test case and `docs/review-mining.md`.
- The opt-in reusable workflows: `verify.yml` (one `make` target in a real browser, for Waypoint's `make control-smoke` and Runway's `make verify`: inputs `make-target`, `working-directory`, `needs-faketime`, `timeout-minutes`, `runs-on`, the Python, Node and browser setup, `fleet-ref`), `screenshot-diff.yml` and `fleet screenshot-diff` (`fleet_tools/screenshot_diff.py`, from Runway's `tools/screenshot_diff.py`, with Pillow as the optional extra `fleet[images]`: inputs `dir`, `comment-marker`, `runs-on`, `dry-run`, `fixture`, `fleet-ref`; the tool runs from fleet's checkout, never the pull request's), `cancel-on-close.yml` (inputs `groups`, `runs-on`) and `tidy-releases.yml` (inputs `image`, `versions`, `retag`, `confirm`, `runs-on`). `tests/test_screenshot_diff.py` carries Runway's tests; the self-test runs `verify.yml` on `tests/fixtures/verify/` and `screenshot-diff.yml` on `tests/fixtures/screenshot-diff/` in dry run. Runway's preview stays in Runway (`docs/drift.md`).
- The Claude Code plugin (`FLEET-PLUGIN`): the marketplace `.claude-plugin/marketplace.json` and the plugin `plugins/fleet/` (version = `VERSION`) with the skills `fix-with-checks`, `design-signoff`, `agent-task` and `review-guidance`, the read-only `fleet-reviewer` agent (the first review's prompt on `git diff origin/main...HEAD`, advisory) and the SessionStart hook, the union of Waypoint's and Runway's configured by the app's `.claude/hooks/fleet.conf` (`PYTHON_VERSION`, `FRONTEND_DIRS`, `APT_PACKAGES`, `NODE_CHECK`) and sourcing `.claude/hooks/session-start.local.sh` last. `fleet sync` now also vendors them (`.claude/skills/fleet-<name>/`, `.claude/agents/fleet-reviewer.md`, `.claude/hooks/fleet-session-start.sh`) and the `tools/fleet` shim (`shim/fleet`, fleet at `.fleet/version` through `uvx`), each marked as vendored, and `fleet drift` fails on a missing, edited or non-executable vendored file or an unknown file under the `fleet-` names (`fleet_tools/vendor.py`); the drift summary counts the vendored files. `fleet checks`' skill check skips `#` comment lines in front matter. `make check` runs `claude plugin validate --strict` with the Claude Code `.github/agent-review/` locks, which `make setup` installs. fleet's own sessions run the plugin's hook (`.claude/settings.json`). `tests/test_hook.py`, `tests/test_sync_vendor.py`; the fixture consumers carry `fleet.conf` and the vendored files.
